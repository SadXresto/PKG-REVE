# Repository audit — 2026-11-16

Scope: full inspection of the existing PKG Studio worktree before the advanced upgrade.
Baseline commit: `chore: establish PKG Studio 0.2.0 baseline`.

## 1. Architecture and technology stack

- **Language/build**: C++20, CMake ≥ 3.21, Ninja; strict GCC/Clang warning set, optional
  ASan+UBSan, GoogleTest fetched via FetchContent.
- **UI**: Qt 6.8 Widgets, Fusion style, custom-painted hex view, QSS rendered from a role→colour
  theme map. No Electron or web runtime.
- **Layers**: `app` (startup, CLI, self-test) → `ui` → `data` (SQLite, settings, themes) →
  `core` (mmap file access, parsers, diagnostics). Core has no widget or SQLite dependency.
- **Persistence**: SQLite schema v1 (`settings`, `recent`, `session`, `analysis_cache`), JSON
  themes under the data directory, rotating logs.
- **Async model**: parsing and searching run on `QThreadPool`/`QtConcurrent`; the UI thread only
  paints bounded windows. Atomic writes via `QSaveFile`/temporary file + rename.

## 2. Existing working features

- Shell: activity bar, explorer, project byte search, recent files/projects, tabs, output and
  diagnostics panel, status bar, command palette, shortcut customization, session restore,
  drag and drop, four themes (Dark, Light, Darcula, Cyberpunk) plus theme editor/import/export.
- Parsers: ELF32/64 (both endians), PE32/PE32+, ZIP, APK (ZIP level), PSP/Vita PKG and PS4 PKG
  container headers; raw fallback with explicit warnings; SQLite analysis cache.
- Hex workspace: mmap-backed hex+ASCII view, 256 KiB sliding window, search with cancellation,
  selection/copy, goto offset.
- Byte editing: opt-in per file, nibble/ASCII entry, undo/redo, modified markers, Save/Save As,
  overwrite confirmation, timestamped backups, atomic whole-file write, unsaved-close prompts.
- Stability tooling: bounds-checked reads, overflow-safe arithmetic, malformed-input tests,
  deterministic fuzz-style tests, performance bounds, ASan/UBSan clean.
- Tests: 59 GoogleTest cases in 17 suites (release and sanitizer builds).
- Docs: README, ARCHITECTURE, BUILD, SECURITY, TESTING, FORMATS, ROADMAP, PLUGIN_SDK plan,
  CHANGELOG.

## 3. Incomplete or absent features (not to be claimed)

- Hex editor: byte insert/delete, multi-range selection, replace, bookmarks/annotations, binary
  compare, patch history, live inspector, signature overlay, binary view.
- Package analysis: confidence reporting, file listing/hierarchy extraction, integrity checks,
  dependency graph, PS5 support, cryptographic utilities.
- Disassembly/debugging: absent (no Capstone, no LLDB).
- AI Studio: absent.
- Plugin runtime: design only; no loader, manifest parser, isolation or sample plugin.
- Developer console: log panel only; no command execution surface.
- Distribution: no installer, portable ZIP, signing or updater; Windows build untested.
- Open source: no LICENSE, CONTRIBUTING, CODE_OF_CONDUCT, INSTALLATION, CI workflow, or
  `.gitattributes`.
- UI: no dockable/floating panels, no workspace layouts, no configurable status bar, no
  notification center, no Void Black design system.

## 4. Bugs and technical debt

- Default theme is Dark and the palette is not a single documented design system.
- Saving is synchronous (bounded and atomic, but large saves occupy the UI thread).
- Insert/delete would change file length; the current document model is same-size only.
- `AppSettings` has no schema version; new preferences rely on defaults.
- Warnings remain in a few older files (conversions in `ProcessInfo`, `ZipParser`,
  `SearchPanel`, test fixtures); core/UI changes are warning-clean.
- Hex view scroll range is capped at `INT_MAX` rows, a limit for extremely large files.
- Analysis is header-level only and cached by path/size/mtime; edits are not reflected until
  save + re-analysis.
- Single-platform verification: no MSVC build, no Windows CI, no installer tests.
- Toolchain for this workspace is bootstrapped into `.venv-tools`/`.tooling`; a runner restore
  can drop the pip venv (recoverable with `scripts/setup-toolchain.sh`).
- No network layer, so no AI or update features exist at all.

## 7. Dependencies and licensing concerns

| Dependency | Version here | Licence | Notes |
| --- | --- | --- | --- |
| Qt 6 (Core/Gui/Widgets/Concurrent/Sql) | 6.8.3 | LGPL-3.0 or GPL-3.0 (commercial option) | Dynamic linking; LGPL obligations apply to distribution |
| SQLite (via Qt SQL driver) | system/Qt plugin | Public domain | No attribution required |
| GoogleTest | 1.15.2 (FetchContent) | BSD-3-Clause | Build/test only, not shipped |
| CMake, Ninja, aqtinstall | build tooling | BSD/Apache/MIT | Not shipped |
| Capstone (planned) | — | BSD-3-Clause | Only if disassembly phase is implemented |
| LLDB (planned) | — | Apache-2.0 with LLVM exception | Optional debugging backend |

Open-source readiness: **no licence file exists**, so the project is currently "all rights
reserved" by default. Before publishing, choose a licence compatible with dynamically linked
LGPL Qt (GPL-3.0-or-later is the simplest compatible choice; MIT is possible with LGPL
obligations documented). Dependencies must be attributed in a NOTICE/third-party file. No
secret, key or private asset is committed; `.gitignore` excludes builds, toolchain, samples,
data directories and logs.

## 8. Phased implementation plan

1. **Audit and baseline** — done in this commit.
2. **Design system + Void Black** — new default theme, Neon Hex, monospace font selection,
   component styling, design doc, contrast tests, screenshots.
3. **Hex editor upgrades** — live byte inspector, signature overlay, same-length replace,
   insert/delete and multi-selection in a later increment (document model change), then
   bookmarks/compare.
4. **Package analysis** — confidence reporting, signature validation surface, PS5 remains
   unsupported until verified; dependency graph only for real relationships.
5. **Disassembly** — Capstone-backed read-only view, architecture detection, honest symbol
   handling.
6. **AI Studio** — provider adapters, local server detection, explicit context preview and
   consent, OS credential storage; cloud disabled by default.
7. **Plugins/console** — manifest loader, permissions, isolation plan, sample plugin.
8. **Performance/crash hardening** — async save with progress, memory caps, recovery.
9. **Windows distribution** — MSVC CI, Inno Setup installer, portable ZIP, checksums.
10. **Open-source release** — LICENSE, CONTRIBUTING, CODE_OF_CONDUCT, INSTALLATION, CI,
    release artefacts.

Phases 4–10 are not started in this session. Nothing above is claimed as working until it is
implemented, built and covered by a check.
