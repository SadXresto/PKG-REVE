# Supported formats — tested scope

PKG Studio only claims what its parsers inspect and what the automated tests cover. Everything
here is **header / directory level**. Payload interpretation, decryption and extraction are out
of scope.

| Format | Detection | Reported data | Not done |
| --- | --- | --- | --- |
| ELF 32/64, LE/BE | `0x7F 'E' 'L' 'F'` + class/data validation | Type, machine, entry point, program headers (type, offset, vaddr, filesz), `PT_INTERP` path | Section headers, symbols, relocations, disassembly |
| PE32 / PE32+ | `MZ` + `e_lfanew` + `PE\0\0` | COFF machine/section count/timestamp, optional header magic, entry point, image base, subsystem, section table (VA, vsize, raw size, characteristics) | Imports/exports, resources, .NET metadata, disassembly |
| ZIP | End-of-central-directory signature scan | Entry count, per-entry name, method, sizes, CRC, local offset (bounded to 4 MiB of directory data) | Extraction, ZIP64 directories, encrypted entries |
| Android APK | ZIP container containing `AndroidManifest.xml` | Everything above plus APK classification and manifest presence | Binary XML decoding, signature verification, DEX analysis |
| PSP / PS Vita PKG | `0x7F 0x50 0x4B 0x47` (`\x7fPKG`) | Revision, type, metadata offset/size, item count, total/data sizes, content ID, per-item table entries with bounds checks | Decryption, extraction, install-package validation |
| PS4 PKG | `0x7F 0x43 0x4E 0x54` (`\x7fCNT`) | 0x1000 container header: type, file/entry counts, table offset and size, body/content offsets and sizes, content ID, DRM type, content type/flags, version date/hash | Decryption, PFS image parsing, extraction |
| Anything else | — | Size plus a 256-byte preview (hex/ASCII) and an explicit "no documented signature" warning | — |

## PS5

PS5 packages are a declared future target, but no PS5 layout has been implemented or verified.
PKG Studio does not claim PS5 compatibility. A PS5 file either matches ZIP/ELF/PE logic or is
reported as unrecognized bytes.

## Validation approach

- Field offsets and endianness were checked against public documentation (psdevwiki /
  shadPS4 notes for the PS4 header; the ELF and PE specifications for those formats).
- Fixtures in `tests/TestData.h` build files byte-by-byte, so parser expectations are encoded
  independently of any third-party tool.
- `samples/` is generated by `tools/make_test_packages.py` and is synthetic.
- No commercial console package has been tested against this build, so the UI and these docs
  deliberately avoid claiming "compatible with all retail PKGs".

## Signature detection (annotations, not parsers)

The bounded scanner recognises: ELF, PE/DOS (PE header verified when possible), ZIP, PNG,
JPEG, PDF, GZIP, 7-Zip, RAR/RAR5, SQLite, WebAssembly, GIF, Mach-O, Java class / universal
binary (ambiguous magic), PSP/Vita PKG and PS4 PKG. Confidence and a validation note are shown
for every hit; embedded matches are reported at reduced confidence and are not treated as the
container format. A signature alone never upgrades the file to a parsed format.

## Saving edited files

Saving rewrites the whole file with pending byte edits applied, at the same size. It never
re-encrypts, re-signs or rebuilds a container: editing bytes inside a signed or encrypted image
will invalidate that signature/encryption, and PKG Studio warns only by scope, not by format
validation. Use backups and only edit files you are authorized to modify.

## Safety properties

- No parser allocates based on an unvalidated 32/64-bit count.
- Every read is bounds-checked; failures produce errors or `partial` results with warnings.
- Truncations at many offsets of every fixture are exercised by the test suite.
- Unknown formats never crash: the raw fallback reads a bounded 256-byte prefix.
